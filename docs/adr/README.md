# Varige arkitekturbeslutninger

Nye beslutninger som endrer arkitekturens varige rammer kan dokumenteres her som `YYYY-MM-DD-kort-navn.md`. Beskriv kontekst, vurderte alternativer, valgt løsning, begrunnelse og konsekvenser; lenk til saken der valget ble tatt.

Les [domenekontrakten](../agents/domain.md) først. En eksisterende autoritativ arkitekturtekst eller wikiartikkel beholder eierskapet; lenk dit i stedet for å kopiere den. Arbeidsstatus og oppgavebeslutninger blir i [GitHub-saken](../agents/issue-tracker.md).

Opprett en beslutningsfil først når et reelt valg er avklart. Denne mappen gir plass og format, ikke oppdiktede historiske beslutninger eller krav om en fil for hver endring.
