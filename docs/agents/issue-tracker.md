# Arbeidsstyring

- Repo: `johan-eilertsen/react-leaflet-explorer`. Stabil prosjektidentitet: `hysvaer`.
- [Prosjektinngang](https://github.com/johan-eilertsen/hysvaer/issues/1); [aktive saker](https://github.com/johan-eilertsen/react-leaflet-explorer/issues).
- Les tildelt sak og dens akseptanse før vesentlig arbeid. GitHub Issues eier omfang, beslutninger, antakelser og bevis. Native milepæler samler leveranseutfall i sitt eget repo.
- [Johan – prosjekter](https://github.com/users/johan-eilertsen/projects/1) eier prioritet, ansvar, status og rekkefølge. Ingen lokal oppgavekø eller statusetiketter.
- Nye saker følger `repo-workflow` og prosjektets eksisterende sakseier. **Kjent begrensning:** `github:create` velger nå `johan-eilertsen/hysvaer` for denne prosjektidentiteten, som avviker fra sakseieren over. En dry-run mot feil repo skal ikke anvendes. Rut nyopprettelse til prosjekteieren for avstemming av den støttede opprettelsesbanen; ikke bruk feil repo, opprett kopisak eller omgå oppretteren med en uavklart manuell handling. Arbeid videre i eksakt tildelt sak når den finnes. Begrensningen endrer ikke eksisterende sakseierskap.
- Publisering og myndighet følger [AGENTS.md](../../AGENTS.md) og `repo-workflow`. Oppdater eksisterende sak ved avslutning.

Kommando for å lese én kjent sak: `gh issue view NUMMER --repo johan-eilertsen/react-leaflet-explorer`. Er saken eksplisitt tildelt i et annet repo, les den eksakte referansen. Opprett ikke en kopi.
